## Overview

QRStream encodes arbitrary files into QR code video streams and decodes them
back. It uses **fountain codes** (RaptorQ / LT) so the receiver can recover
the original file even when some frames are lost — no feedback channel needed.

```
Encoder                                     Decoder
┌──────────┐ Fountain code   ┌──────────┐   Screen cap   ┌──────────┐   QR detect    ┌──────────┐
│   File    │ ──────────────→ │ QR Video │ ────────────→ │  Video   │ ────────────→ │ Recovered│
└──────────┘  zlib + base45   └──────────┘                └──────────┘   Fountain     │   File   │
                                                                          decode       └──────────┘
```

## Data Flow

### Encode Pipeline (`qrstream encode <file> [-o out.mp4]`)

```
encoder.py                                         related modules
──────────────────────────────────────────────────────────────────────
_load_payload()
  ├─ Read file bytes or mmap (>10MB)               _compat.py
  └─ Optional zlib compression

auto_blocksize()                                    protocol.py
  └─ Choose block size based on file size & QR version

LTEncoder / RaptorQEncoder                          lt_codec.py
  └─ Generate fountain-coded blocks                 raptorq_codec.py

  └─ Serialize block → header + data + CRC32

generate_qr_image / generate_qr_module_image        qr_utils.py
  └─ Encode payload → base45 → QR symbol (zxing-cpp)

VideoWriter thread                                  (PyAV / av)
  └─ BGR frames → H.264/MP4V/MJPEG → .mp4/.avi

_DisplayVideoSink (--display -o)                    display_cache.py
  └─ Best-effort realtime writer with deferred frame fallback
```

Entry function: `encode_to_video()` (line ~415 in encoder.py)
- Uses `ThreadPoolExecutor` for parallel QR generation when `--workers > 1`
- Default: `workers=1` (video writer is usually the bottleneck)
- Codec: H.264 (default), MP4V, MJPEG

### Decode Pipeline (`qrstream decode <video> -o <output_file>`)

```
decoder.py                                         related modules
──────────────────────────────────────────────────────────────────────
_open_video_container()                             (PyAV / av)
  └─ Open video, validate codec

Frame reader thread
  └─ Decode frames → BGR numpy arrays

try_decode_qr / try_decode_qr_with_bbox             qr_utils.py
  └─ zxing-cpp detection (GIL-free C++)
  └─ Adaptive downscale based on QR module density

  └─ Parse header, base45/base64 decode, CRC32 validate

  └─ Fountain-code recovery                        raptorq_codec.py

  └─ Reconstruct & write output file
  └─ Optional zlib decompress
  └─ GE rescue (LT only): Gaussian elimination fallback
```

Entry functions: `extract_qr_from_video()` → `decode_blocks_to_file()`
- Uses `ThreadPoolExecutor` for parallel QR detection (zxing-cpp releases GIL)
- Probe phase: samples first N frames to estimate detection rate
- Adaptive sample rate: skips frames when detection rate is high
- `ProbeObservation` namedtuple (10 fields) for probe pipeline

### Display Mode (`qrstream encode <file> --display [-o out.mp4]`)

```
encoder.py                                         related modules
──────────────────────────────────────────────────────────────────────
encode_to_display()
  ├─ Pure display (no -o): subprocess producer      display_cache.py
  │   └─ Encode in child process → SharedFrameBuffer (shm)
  │   └─ Qt GUI reads packed frames from shared memory
  │   └─ Eliminates GIL contention between encoder & GUI
  │
  └─ Display + video (-o): thread producer
      └─ ModuleFrameCache (bit-packed, 1 bit/module)
      └─ _QRStreamWindow (PySide6)                   display_player_qt.py
      └─ _DisplayVideoSink: non-blocking offer/finalize
```

Key display-mode components:
- `ModuleFrameCache`: bit-packed frame store, `full` or `window` mode
- `SharedFrameBuffer` / `SharedProducerState` / `SharedBufferCacheAdapter`: shm IPC
- `_QRStreamWindow`: dark-themed Qt player with timeline scrubber, FPS warning
- `_PixmapCache`: O(1) OrderedDict LRU for decoded pixmaps

## Fountain Code Architecture

### LT Codes (`lt_codec.py`)
```
PRNG (prng_version=1, SplitMix64)
  └─ Non-linear seed mixing, no warmup needed
  └─ Legacy prng_version=0 (LCG + 5-round warmup) kept for test fixtures

Robust Soliton Distribution (c=0.1, delta=0.5)
  └─ Ideal Soliton ρ(d) + τ(d) adjustment

BlockGraph
  └─ Belief Propagation decoder (in-place numpy XOR)
  └─ XOR via numpy vectorisation (10-50x faster than pure Python)
  └─ Gaussian Elimination rescue for stalled graphs
```

### RaptorQ (`raptorq_codec.py`)
```
RaptorQEncoder
  └─ Wraps `raptorq` Rust crate (PyO3 bindings)
  └─ Systematic: source symbols emitted directly from data (no encoding)
  └─ Lazy encoder init: only creates raptorq encoder when repair packets needed
  └─ mmap-backed: keeps large files file-backed, no eager copy

RaptorQDecoder
  └─ Receives source + repair packets → internal recovery
  └─ No GE rescue needed (built-in decoder handles all recovery)
  └─ PayloadId: SBN(8bit) || ESI(24bit)
```

Overhead defaults (`overhead_policy.py`):
| Codec   | Min   | Recommended | Default |
|---------|-------|-------------|---------|
| LT      | 1.20  | 1.50        | 2.00    |
| RaptorQ | 1.05  | 1.10        | 1.20    |

## Protocol Versions

### V3 (LT, default pre-0.10)
- 24-byte fixed header + data + 4-byte CRC32 = 28 bytes
- Uses `pack_v3()` / `unpack()`; parsed into `V3Header` dataclass
- Struct fields: `version`, `flags` (compressed/high-density/prng_version bitmask),
  `filesize`, `blocksize`, `block_count`, `seed`, `block_seq`, `reserved`
- On-wire: base45 (default) or base64; legacy COBS kept for backward compat decode

### V4 (RaptorQ, default ≥0.10)
- Same 28-byte overhead layout as V3
- Uses `pack_v4()` / `unpack()`; parsed into `V4Header` dataclass
- Struct fields: `version`, `flags`, `filesize`, `symbol_size`, `symbol_count`,
  `esi` (PayloadId, replaces V3 `seed`), `block_seq`, `reserved`

### Wire encoding
- Default: **base45** → QR alphanumeric mode (5.5 bits/char)
- Legacy: base64 → QR byte mode (kept for backward-compatible decode)
- Pre-0.6: COBS + latin-1 (decoder multi-strategy try chain keeps these playable)

### FPS ceiling & phase-drift safety margins

Camera and display clocks are never synchronised in the two-device,
one-way-link workflow.  When the encode FPS equals (or is rounded up to)
the capture FPS, phase drift causes systematic frame loss that grows with
recording duration.

Two layers enforce safety:

1. **Strict ceiling** (`_capture_fps_ceiling`): largest integer strictly
   below the raw capture fps.  59.94 → 59, 60.00 → 59.
2. **Per-tier margin** (`_TIERS["fps_margin"]`): each tier reserves
   additional headroom.

| Tier         | `fps_margin` | 59.94 fps ceiling | 29.97 fps ceiling |
|--------------|:------------:|:-----------------:|:-----------------:|
| aggressive   | 5 %          | 56                | 28                |
| balanced     | 10 %         | 53                | 26                |
| safe         | 15 %         | 50                | 25                |

`_capture_fps_nominal` (nearest-integer round) is used **only** for
informational messages and cadence-gain heuristics — never for safety
filtering.

The optimizer runs once per tier with its own ceiling so that each tier
sees only the FPS candidates it is allowed to recommend.
