│ SUBPROCESS IPC ANALYSIS: Why It Would Fail                                     │
└─────────────────────────────────────────────────────────────────────────────────┘

    Proposal: Move producer thread to subprocess

    Per-Frame IPC Cost (packed frame ~3.7 KB):
    ┌─────────────────────────────────────────────────────┐
    │ Subprocess → Parent (via pipe):                      │
    │   • pickle serialization:          0.5–1 ms         │
    │   • pipe write + read:             0.5–1 ms         │
    │   • unpickle deserialization:      0.5–1 ms         │
    │ ─────────────────────────────────────────────────    │
    │ Total per frame:                   ~2–3 ms          │
    │                                                      │
    │ But producer generation cost:     ~1.8 ms           │
    │ ─────────────────────────────────────────────────    │
    │ Net: Add 2–3 ms to existing 1.8 ms = 4.6 ms         │
    │      2.6× SLOWER (❌ loss)                           │
    └─────────────────────────────────────────────────────┘

    Savings from subprocess:
    ┌─────────────────────────────────────────────────────┐
    │ GIL contention:                     ~$0             │
    │ Reason: zxing-cpp releases GIL anyway               │
    │        Other ops are lock-free or < 1 µs locked     │
    └─────────────────────────────────────────────────────┘

    Shared State Complexity:
    ┌─────────────────────────────────────────────────────┐
    │ Need to share:                                       │
    │   • Fountain encoder state (K, blocksize, seed)      │
    │   • ModuleFrameCache (NumPy arrays)                  │
    │   • DisplayProducerState (counters, events)          │
    │                                                      │
    │ Options:                                             │
    │   1. pickle encoder + cache on each frame (~2–3 ms) │
    │      ❌ IPC overhead > generation cost              │
    │                                                      │
    │   2. Pre-compute all packed frames                   │
    │      ❌ Adds latency, defeats streaming benefit      │
    │                                                      │
    │   3. Use multiprocessing.shared_memory               │
    │      ❌ Still requires locks + IPC overhead          │
    │      ❌ Complex, error-prone (segment lifecycle)     │
    └─────────────────────────────────────────────────────┘

    Conclusion: ❌ Subprocess IPC would ADD ~2–3 ms overhead
                   with NO GIL benefit (already released).
                   DO NOT IMPLEMENT.
